### Phase 3 — Performance Mode Consolidation

*Problem: two rows of chrome (context bar + dashboard) eat real estate. Some actions are always visible that are only needed during setup, not on stage. Screen feels shallow and icon-heavy without clear priority.*

**Shipped bar layout:**
```
┌─────────────────────────────────────────────────────────────────┐
│  [SET 1]  [SET 2]  [SET 3]     9:45 PM    ☀   [  🔍  ]  ···  ✕ │  ← Row 1: 52dp
├─────────────────────────────────────────────────────────────────┤
│  ←   [G]  Song Title Here             [120 BPM] [CAPO 2]    →   │  ← Row 2: 72dp
└─────────────────────────────────────────────────────────────────┘
```
- **Row 1:** Pill-shaped SET tabs (tappable, set-colored when active) | clock | ☀ dark/light | wide search | ··· overflow (save/load) | ✕ exit
- **Row 2:** 56dp prev/next arrows | compact key badge | SONG TITLE 22sp (set-colored) | status pill (BPM+capo+lead) | transposition ⚠
- **Removed from chrome:** Edit (library post-gig only)
- **Set switching:** `getFirstSongIdForSet()` in ViewModel → `onNavigateToSongInSet(songId, setNumber)` in nav
- **Touch targets:** 48dp icons in Row 1, 56dp arrows in Row 2 — stageable with one hand
- **Chart padding:** 152dp → 128dp (significant real-estate gain)
