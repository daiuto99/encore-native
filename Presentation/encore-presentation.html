Design Philosophy

Built for the stage.
Not the studio.

Four principles that shape every decision — from gesture design to cloud sync.

01

Stage-First Design

Every pixel is optimized for the moment you're in front of a crowd. Performance mode is full-screen, high-contrast, and finger-friendly. No menus. No distractions. Just the chart.

02

You Own Your Library

Songs are plain Markdown files with YAML front matter. No proprietary lock-in, no binary blobs. Your charts live in Google Cloud Storage — readable, portable, and yours.

03

The Two Screens Rule

Manage your library on the web manager. Manage your sets on the tablet. Each surface does exactly one job. The library screen never reaches into set management and vice versa.

04

Sync Without Fear

Bidirectional GCS sync with conflict detection, per-song locking, and a resolution UI. The tablet never silently overwrites web edits — every divergence surfaces as a choice.

Key Change

Play in any key.
One tap.

Every song tracks two keys independently — the original key locked at import, and a display key you can shift up or down by half steps. Every chord in the chart transposes in real time. Encore picks sharps or flats automatically based on key context.

[Verse]
`[G]` Amazing grace how sweet
`[C]` the sound that
`[G]` saved a wretch like me
 `[D]` / `[G]`
[Verse]
`[Bb]` Amazing grace how sweet
`[Eb]` the sound that
`[Bb]` saved a wretch like me
`[F]` / `[Bb]`
🎼

Original Key Locked

original_key is set once at import and never changes. It's the reference point for all transposition — always recoverable with "Reset to original" in the edit sheet.

↕

Half-Step Shifting

Tap + or − in the song edit sheet to raise or lower the display key one semitone at a time. The shift is stored as display_key — calculated on render, not stored in the chart body.

b/#

Smart Sharp / Flat Spelling

Going up uses sharps (C → C#). Going down uses flats (C → Db). Flat keys (F, Bb, Eb, Ab…) always render with flat spelling regardless of direction — matching standard notation conventions.

🎸

Slash Chord Transposition

Both parts of a slash chord transpose independently. G/B in G becomes Bb/D in Bb. Correctly handles all compound inversions.

⚡

Real-Time in Performance Mode

Transposition is computed at render time — every chord token in every line is shifted in a single pass. No re-saving required. Change the key and the chart updates instantly.

🔄

One-Tap Reset

A "Reset to original" button appears in the edit sheet any time display_key ≠ original_key. Tap it to snap back. The indicator line shows the current shift — e.g. Original: G → Bb.

⚡

One-Tap Normalize

Tap the wand icon on any song in the library. Claude Sonnet rewrites it to clean Encore format and saves it back to Room DB automatically.

🎼

Chord Inline Conversion

Stacked chord/lyric lines get converted to Encore's inline [G]word notation. Chords land on the correct syllable every time.

📋

YAML Front Matter

Missing or malformed headers are reconstructed — title, artist, key, tempo, time signature — so every song is first-class in the library.

🗂️

Section Detection

Unlabeled blocks are identified as verse, chorus, bridge, or intro based on repetition patterns and content, then tagged with proper ## headers.

🔑

Key Preservation

The original key is detected from chord content even when missing from the header. Normalization never transposes — it only restructures.

☁️

Auto-Upload After Normalize

Once normalized, the updated chart is uploaded to GCS in the background — keeping cloud and tablet in sync without any extra steps.

Library Sync

Your library. Everywhere.
Always current.

Three ways to get songs in — folder sync from a local directory, individual file import, or cloud sync from GCS. All roads lead to the same Room database on the tablet, the same GCS bucket in the cloud.

📁

Folder Sync (Web)

Connect a local folder via the File System Access API. Encore walks the directory tree, loads every .md file, and makes them editable — no upload step. Changes are written directly back to disk.

📥

File Import (Android)

Open the multi-file picker to import individual .md files. Encore parses YAML front matter, extracts key and metadata, deduplicates by song ID, and adds to the library in one batch.

📂

Sync Folder (Android)

Grant persistent access to a DocumentTree URI. Encore re-scans the folder on demand — new files are imported, unchanged files are skipped. The URI persists across app restarts.

☁

GCS Cloud Sync

Every edit on the tablet triggers a background upload. Every open pulls the latest from GCS. The manifest is cached for 60 seconds — invalidated before each upload to catch concurrent web edits.

🔁

Background Poller

A background worker periodically checks GCS for changes made on the web manager. New or updated songs are downloaded and merged into the local database without user interaction.

⚠

Conflict Detection

Local hash vs remote hash comparison on every upload. Divergence = conflict. The song gets a ⚠ badge and a resolution dialog — keep local or pull remote — before any write happens.

Architecture

Service account JWT.
No Play Services. No OAuth2.

After exhausting three OAuth2 approaches (all blocked by Android's Play Services environment), the tablet authenticates to GCS using RSA-SHA256 JWT signed by a service account — fully self-contained, no user interaction required after first login.

Manifest Cache + Invalidation

Remote manifest cached for 60s to reduce GCS reads. Pre-upload conflict check calls invalidateCache() to force a fresh manifest — ensuring web edits are never silently overwritten.

The Format

Plain Markdown.
Structured for the stage.

Every song is a .md file with a YAML front matter block followed by a body in Encore format. Human-readable. Version-controllable. Performable.

---
title: Don't Stop Believin'
artist: Journey
display_key: E
original_key:E
is_lead_guitar:false
bpm: 120
---

[Verse 1]
`[E]` Just a small town girl `[B]` livin' in a lonely world
`[C#m]` She took the midnight train `[A]` goin' anywhere

[Chorus]
`[E]` Don't stop [h]believin'[/h], `[B]` hold on to the [h]feelin'[/h]
`[C#m]` Streetlight `[A]` people

[Solo]
`[E]` / `[B]` / `[C#m]` / `[A]` /
📄

YAML Front Matter

Title, artist, display_key, original_key, is_lead_guitar, bpm, capo. Parsed on import and stored in Room DB. The original_key is immutable once set — display_key tracks transposition.

🎸

Inline Chord Notation

`[G]` placed immediately before the syllable. Renders gold in performance mode. Transposed in real time when display_key ≠ original_key.

🏷

Section Headers

[Verse 1] bracket format. Each known section type (Verse, Chorus, Bridge, Solo…) gets a distinct color and bold label in performance mode.
